## Attaques tentées

Caractères de contrôle et emoji coupés dans les textes envoyés au node XML ; README sans titres ou en `.rst` ; dépôt sans release ; URL `orgs/acme` et `b.` ; trois dépôts dont un en échec ; réponse du modèle avec un identifiant de contexte altéré ; réponse du modèle contenant une image distante et un lien `javascript:` ; rapport servi par la réutilisation après un échec Notion ; fichier de dépendances en erreur 5xx ; inventaire où un nom d'outil est une sous-chaîne d'un nom de dépôt ; décision éditée après coup ; destinataire de l'e-mail piloté par le formulaire (sans résultat : l'adresse est fixée dans `CONFIGURATION`) ; injection d'expression par l'objectif ou l'URL (sans résultat : ce sont des données, la regex reconstruit owner/name) ; HTML de l'e-mail (échappé) ; formulaire sans credential (n8n refuse l'activation) ; boucle infinie (aucune) ; secrets dans l'historique git (18 commits, 0 résultat) ; validate et lint sur copie ; build régénéré (identique).

## Hypothèse la plus fragile

Que le modèle refuse d'obéir à un README ou à une issue hostile : la seule barrière contre l'écriture d'une URL piégée dans la page Notion est le prompt (C1). Si l'alias `-latest` change de comportement ou si un dépôt est malveillant, rien dans le code ne retient la fuite du profil et de l'inventaire.
